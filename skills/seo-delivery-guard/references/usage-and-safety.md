# Usage and safety

Use this reference for prerequisites, permissions, inputs, outputs, refusal decisions, or troubleshooting.

## Prerequisites

- A concrete website, page, content change, audit result, release, or regression question.
- Access only to the project files, public URLs, and external properties required by the current task.
- The project's current rule owners and real validation or release entry points when implementation is requested.

The Skill itself needs no crawler, API key, executable, Python runtime, or operating-system-specific component. Optional analyzers and first-party data sources remain optional and separately authorized.

## Inputs

Accept the minimum necessary combination of URL, repository path, intended change, target audience, intended indexability, locales, audit findings, and sanitized evidence. Do not request credentials, cookies, private keys, complete analytics exports, private content, or sensitive user data when a narrower input can answer the question.

## Outputs

Return:

- applicable rules and scope;
- blockers, advice, unknowns, and rejected recommendations;
- evidence source, date, confidence, and limitation;
- accepted implementation action;
- validation layer and release consequence;
- production status and delayed external outcomes.

Do not expose complete secrets or sensitive source material in reports.

## Refuse or narrow

Refuse requests to manipulate rankings through spam, fabricate experience or evidence, create doorway or mass keyword pages without user value, conceal private content with crawler directives, bypass platform access controls, expose confidential data, or imply search-engine certification or guaranteed outcomes.

Narrow an overbroad request to the authorized website, URL class, repository, property, and external action.

## Troubleshooting

- If a URL is unreachable, report the observation and do not guess its content.
- If project rules conflict, stop the risky action and identify the authoritative owner that must be resolved.
- If an analyzer fails, preserve successful evidence, name the missing discipline, and do not mark it passed.
- If first-party data is unavailable, distinguish unknown external state from verified public-page behavior.
- If candidate and production differ, treat production as the current user-facing fact and follow the project's repair or rollback process.
- If a search result has not refreshed, verify the engineering contract and record recrawl or reevaluation as pending rather than repeatedly changing the page.
