# Content and indexability

Use this reference when adding, substantially changing, translating, consolidating, or retiring public content.

## Before creating a URL

Require evidence for:

- a specific audience and decision or task;
- why the strongest existing page cannot satisfy it;
- the page's distinct information, analysis, experience, or executable help;
- reliable sources for changeable facts;
- the intended indexability and internal discovery path;
- the conditions for later improvement, merger, noindex, or removal.

Search volume, keyword coverage, advertising inventory, page count, or AI-generation efficiency is not independent user value. If the evidence does not support a distinct page, improve or consolidate the strongest existing URL instead.

## Research and review

Separate verified search-property evidence from a search-demand hypothesis. Never invent volume, difficulty, ranking opportunity, user experience, authorship, testing, statistics, freshness, certification, or partnerships.

For material factual content, prefer direct primary sources and record when each changeable fact was checked. Automated structure, length, or AI self-review does not replace editorial review of accuracy, originality, usefulness, language quality, policy risk, and visible presentation.

## Indexability decision

Use an explicit decision:

- `keep`: the current page remains the strongest useful URL;
- `improve`: strengthen the existing URL rather than create a near duplicate;
- `merge`: consolidate overlapping value and signals into the strongest equivalent;
- `noindex`: keep a useful accessible page out of search while preserving crawl access to the directive;
- `remove`: return an honest removal status when no useful page should remain.

When systematic crawled-not-indexed, duplicate, soft-404, canonical, or redirect problems appear, pause expansion of that URL class and resolve the pattern first.

## URL retirement

Use a permanent redirect only when a real equivalent destination preserves the user's intent. Otherwise return an honest `404` or `410`. Do not send retired URLs to an unrelated homepage, create wildcard soft redirects, restore obsolete doorway pages, or keep removed URLs in sitemaps, hreflang, or internal links.

## International content

Each indexable locale must preserve the same facts, limitations, sources, machine contract, indexability intent, and user value while using professionally reviewed language. Machine translation, template substitution, character counts, and English fallback cannot prove parity. Keep an unreviewed locale out of sitemaps and hreflang rather than presenting it as complete.
