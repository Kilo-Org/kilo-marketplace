# Evidence handling

Shared by every Tarosec skill. Canonical copy: `references/evidence-handling.md`;
skill copies are generated by `scripts/sync_shared.py`.

## Provenance

For each evidence item record (see `schemas/evidence.schema.json`): source,
collection method, collector, collection time, original timestamp **and** its
time zone or offset (or `unknown`), artifact path, SHA-256 when a file exists,
sensitivity, and integrity limits. Unknown stays explicit; never guess a zone or
silently re-order simultaneous events.

A matching hash proves byte consistency with a reference, not authenticity or
chain of custody. Preserve a hash mismatch; never update the reference to pass.

## Originals and report views

Keep originals unchanged in a private, authorized evidence root. Reports cite
evidence IDs and use a separate, sanitized view with its own identity and hash.
Redact secrets by type and location (`AWS access key at config/prod.env:3`);
never repeat full credential values in reports, commands or logs.

## Claim strength

Keep these independent — never merge them into one "status":

| Axis | Values |
| --- | --- |
| Severity | Critical, High, Medium, Low, Informational (with rationale) |
| Confidence | Confirmed, Likely, Unknown |
| Vulnerability status | Potential weakness, Verified vulnerability, Simulation observation, Informational, False positive |
| Incident classification | Confirmed incident, Suspected incident, Benign event, Simulation only, Inconclusive |
| Detection outcome (Purple) | see `tarosec-purple` outcome table |

A static source trace, an executed lab reproduction, and observed real-world
exploitation are different claim strengths; name which one you have.

## Failed, missing and unrun work

A tool that failed, timed out, was unavailable or never ran is **Not Run** or
**Failed** — never a clean result. Missing logs, sensor gaps and unknown clock
offsets are reported as gaps, not as evidence of absence.
